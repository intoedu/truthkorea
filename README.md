# 트루스코리아 홈페이지

**트루스코리아(TRUTHKOREA, TK국민주권운동) 홈페이지**(국민주권운동.com)를 새로 만든 웹사이트입니다.
표어: **자유대한민국 5,000만 국민주권운동!**

어르신들이 쉽게 쓰실 수 있도록 **큰 글자, 늘 보이는 글자 메뉴, 크게 누르는 단추, 단순한 화면**으로 만들었습니다.
옛 홈페이지 **처음 화면에 있던 글 20개**(사진 17장, 두 게시판에 똑같이 있던 글 하나는 숨겨 19개가 보임)와 비전선언문·후원 안내 글을 글자 그대로 옮겨 왔고,
관리자가 새 글을 쓸 수 있는 **관리자 화면**(`/admin/`)이 있습니다.
그보다 오래된 옛 글은 단체의 결정으로 옮기지 않았습니다. 옛 사이트를 닫을 때까지만 거기에 남아 있으므로, 남겨 두려면 닫기 전에 옛 사이트를 백업해 두어야 합니다(`CONTENT-TODO.md`).

- 빌드 과정이 없는 정적 사이트입니다. HTML·CSS·자바스크립트 파일을 그대로 올리면 됩니다.
- 글은 처음에는 저장소 안의 `data/posts.json`에서 읽고, Supabase(글 저장소)를 연결하면 Supabase에서 읽습니다.
- 회원 가입, 방문자 입력 칸(신청서·댓글)은 없습니다(단체의 결정). 연락은 전화와 이메일로만 받습니다.
- 공개 화면은 바깥 서버(CDN, 글꼴 서비스, 통계 도구)에 아무것도 요청하지 않습니다. 유튜브 영상은 방문자가 ‘영상 보기’를 누를 때에만 불러옵니다.

## 어르신을 위한 화면 특징

- 본문 글자는 휴대전화 19px, 컴퓨터 20px 이상, 줄 간격 1.75입니다. 글자와 바탕의 명암 대비는 모두 가장 높은 기준(WCAG AAA, 7:1 이상)을 지켰습니다.
- 화면 맨 위 **글자 크기 단추**(보통 · 크게 · 아주 크게)로 모든 글자를 키울 수 있고, 고른 크기는 다른 쪽에서도 유지됩니다.
- 메뉴는 숨기지 않고 늘 글자로 보입니다(햄버거 단추 없음). 지금 보고 있는 쪽은 진한 남색과 아래 노란 줄로 표시됩니다.
- 누르는 곳은 모두 가로·세로 48px 이상(대부분 56px)이고, 링크에는 밑줄이 있습니다.
- 휴대전화에서는 머리글을 낮게 만들어(글자 크기 줄 한 줄, 메뉴 3칸) 첫 화면에 쪽 제목과 내용이 함께 보입니다. 후원하기 화면은 맨 위에 후원 계좌와 ‘계좌번호 복사’ 단추가 있습니다.
- 휴대전화에서는 화면 아래에 **전화 걸기 · 후원하기 · 맨 위로** 막대가 늘 있습니다. 컴퓨터에서는 머리글 오른쪽에 큰 ‘전화 문의’ 단추가 있습니다.
- 움직이는 그림, 자동으로 넘어가는 슬라이드, 자동 재생이 없습니다.
- 키보드만으로도 쓸 수 있고(‘본문 바로가기’, 굵은 초점 표시), 인쇄하면 메뉴는 빠지고 내용만 나옵니다.
- 가로 320px 휴대전화에서 글자를 ‘아주 크게’ 해도 화면이 옆으로 밀리지 않습니다.
- 다른 사이트로 가는 링크(서명운동, 유튜브)에는 ‘다른 사이트’라고 적어 두었고, 새 창이 아니라 같은 창에서 열립니다(뒤로 가기 단추로 돌아올 수 있음).
- 옛 홈페이지 글 주소(`/bbs/board.php?bo_table=…&wr_id=…`)로 들어오면 옮긴 글은 새 홈페이지의 같은 글로, 옮기지 않은 글은 그 분류의 목록(종합뉴스·TK 뉴스·진실알리기·행사·세미나)으로 옮겨 줍니다. 없는 글 화면으로는 보내지 않습니다(카카오톡으로 퍼진 옛 링크용, `assets/js/legacy-redirect.js`).

저장소 폴더에서 아래 명령을 실행한 뒤 브라우저에서 `http://localhost:8000/` 을 엽니다.


## 글(뉴스·영상·행사)은 어떻게 나오나요

`assets/js/posts.js`가 글을 읽어 화면에 그립니다.

1. **`assets/js/config.js`가 비어 있으면** (지금 상태) → 저장소 안 `data/posts.json` 파일을 읽습니다.
   글을 바꾸려면 이 파일을 고쳐서 다시 올려야 합니다. 관리자 화면은 ‘아직 연결 전입니다’라고만 보입니다.
2. **`config.js`에 Supabase 주소와 공개 키를 넣으면** → Supabase에서 읽습니다
   (`GET {주소}/rest/v1/posts?select=…&is_published=eq.true&order=published_at.desc,id.desc&limit=…&offset=…`, 머리글 `apikey`(예전 `eyJ…` 키일 때는 `Authorization: Bearer {공개 키}`도 함께)).
   이때부터 관리자가 `/admin/`에서 쓴 글이 바로 홈페이지에 나옵니다. `data/posts.json`은 더 이상 읽지 않습니다.

어느 쪽이든 글 제목·본문은 **글자로만** 넣습니다(HTML로 해석하지 않음). 그래서 글에 `<script>` 같은 것이 들어 있어도 실행되지 않고 글자로 보입니다.

- 본문: 빈 줄은 새 문단, 한 줄 바꿈은 줄 바꿈으로 보입니다. `http://`, `https://`로 시작하는 주소는 저절로 링크가 됩니다.
- 본문이 제목과 똑같으면 본문은 다시 보이지 않습니다.
- 유튜브: 썸네일 없이 큰 ‘영상 보기’ 단추가 먼저 보이고, 누르면 그 자리에서 `youtube-nocookie.com` 영상이 나옵니다. 아래에 ‘유튜브에서 보기’ 링크가 있습니다.
- 사진: 사이트 안 주소(`assets/uploads/…`)와 `https://` 주소 둘 다 됩니다. 늦게 불러오기(lazy)와 가로·세로 크기가 들어 있습니다. 사진 설명 줄(`caption`)이 있으면 사진 바로 아래에 보이고, ‘사진 크게 보기’는 원본(`full`, 없으면 `src`)을 엽니다. 목록에는 작은 그림(`thumb`, 없으면 `src`)을 씁니다.
- 사진·영상 자리: `after`(사진), `video_after`(첫 영상), `extra_videos[].after`(둘째 이후 영상)가 있으면 ‘그 수만큼의 문단 뒤’에 놓습니다(0이면 맨 위). 없으면 첫 영상은 맨 위, 사진은 본문 아래입니다. 옛 글은 옛 화면과 같은 자리에 놓이도록 이 값이 들어 있습니다.
- 숨은 링크: `links`(`[{ "text": "자세히보기", "href": "https://…" }]`)가 있으면 본문에서 그 글자가 처음 나오는 곳을 링크로 만듭니다(본문 글자는 바꾸지 않음).
- 글 보기 화면에는 ‘공유하기’(휴대전화가 지원할 때)와 ‘글 주소 복사’ 단추가 있어 카카오톡으로 보내기 쉽습니다.
- 불러오는 중·글 없음·오류(‘다시 불러오기’ 단추) 상태가 모두 쉬운 우리말로 나옵니다. 자바스크립트가 꺼져 있으면 그렇다고 알려 줍니다.

### data/posts.json 형식

글 배열이며 최신 글이 앞에 옵니다.

```json
{
  "id": "legacy-TK_NEWS-22",            // 글번호 (영문·숫자·-·_ 만)
  "category": "tknews",                 // broadcast=종합뉴스, tknews=TK 뉴스, truth=진실알리기, event=행사·세미나
  "title": "제목",
  "published_at": "2025-10-05T18:59:41+09:00",
  "body": "문단\n\n다음 문단",          // HTML 아님, 없으면 ""
  "youtube_id": null,                   // 또는 "HPuDXqXClMk"
  "video_after": 3,                     // (선택) 첫 영상을 3번째 문단 뒤에. 없으면 맨 위
  "extra_videos": [{ "id": "8kpbBiheqIU", "after": 2 }],  // (선택) 둘째 이후 영상
  "images": [{ "src": "assets/uploads/legacy/TK_NEWS-22-1.jpg", "alt": "사진 설명(화면 읽기용)", "width": 600, "height": 329,
               "caption": "사진 아래에 보일 글(선택)", "after": 1,           // (선택) 1번째 문단 뒤
               "thumb": "…-thumb.jpg", "full": "…원본…" }],                // (선택) 목록용 작은 그림, 크게 보기용 원본
  "links": [{ "text": "자세히보기", "href": "https://…" }],          // (선택) 본문 글자에 거는 링크
  "source_url": "http://…옛 주소…",
  "show_on_home": true,                 // 처음 화면 ‘최근 소식’에 보일지
  "is_published": false,                // (선택) false면 어디에도 안 보임. 없으면 보임
  "event_start": "2025-09-19",          // (선택, 행사) 행사 날짜
  "event_end": "2025-09-21"             // (선택, 여러 날 행사)
}
```

옛 사이트에서 두 게시판(진실알리기, 윤석열 대통령)에 똑같이 올라 있던 ‘국민께 드리는 말씀’은 한쪽을 `"is_published": false`로 숨겨 두었습니다
(`legacy-PresidentYoon-8` 숨김 → `legacy-truth-12`가 보임).
숨긴 쪽의 옛 주소나 `post.html?id=…`로 들어오면 보이는 쪽으로 옮겨 줍니다(`assets/js/legacy-redirect.js`의 `SAME`, `assets/js/posts.js`의 `LEGACY_SAME`).
옮긴 옛 글의 번호는 `assets/js/legacy-redirect.js`의 `MOVED`에 있습니다. 이 목록에 없는 옛 글 주소는 그 분류의 목록으로 갑니다.
옛 글을 `data/posts.json`에 더 옮겨 넣으면 `MOVED`에도 그 번호를 넣습니다.
옛 글 번호(`legacy-게시판-번호`)로 `post.html?id=…`를 열었는데 글이 없으면 ‘글을 찾을 수 없습니다’와 함께 그 분류의 목록으로 가는 단추가 나옵니다.

### 옛 사진 파일

- `assets/uploads/legacy/게시판-번호-순서.확장자`는 옛 홈페이지의 원본 파일을 **바이트까지 그대로** 복사한 것입니다.
- 100KB가 넘는 그림 14장에는 목록용 작은 그림 `…-thumb.jpg`(너비 480px, 품질 80)를 만들었습니다. 가장 큰 사진도 800KB가 안 되어 화면용 사본은 따로 두지 않았습니다.
  (나중에 1MB가 넘는 그림을 넣을 때는 화면용 사본을 `src`, 원본을 `full`(‘사진 크게 보기’)로 둡니다.)
- 옮긴 글 20개의 글과 사진에는 단체가 쓰지 말라고 한 다른 계좌번호가 없습니다(그 번호가 든 포스터 두 장은 옮기지 않은 옛 글에 있었습니다).

## Supabase 연결하기

Supabase는 글과 사진을 저장하고, 관리자 로그인을 맡는 서비스입니다. 아래 순서대로 한 번만 하면 됩니다.

1. **프로젝트 만들기**: <https://supabase.com> 에서 새 프로젝트를 만듭니다. 지역(Region)은 `Northeast Asia (Seoul)`을 권합니다.
   데이터베이스 비밀번호는 안전한 곳에 적어 둡니다.
2. **표와 권한 규칙 만들기**: 대시보드 왼쪽 **SQL Editor** → 새 쿼리에 `supabase/migrations/0001_init.sql` 내용을 모두 붙여 넣고 **Run**.
   - 만들어지는 것: `public.posts`(글), `public.admins`(관리자 목록), `public.is_admin()` 함수, 행 단위 보안(RLS) 규칙, 사진 저장소 `post-images`(공개 읽기).
   - 규칙 요약: 게시된 글은 누구나 읽기 / 숨긴 글 읽기와 쓰기·고치기·지우기, 사진 올리기·지우기는 `admins` 표에 있는 사람만 / `admins` 표는 화면에서 아무도 바꿀 수 없음.
   - (Supabase CLI를 쓰면 `supabase link` 후 `supabase db push`로도 됩니다.)
3. **옛 글 넣기**: 같은 SQL Editor에서 `supabase/seed.sql` 내용을 붙여 넣고 **Run**. 옛 처음 화면의 글 20개가 들어갑니다(19개가 보이고 같은 글 하나는 숨김, 여러 번 실행해도 겹치지 않음).
   옛 사진 주소는 `assets/uploads/legacy/…` 그대로이므로, 홈페이지를 올릴 때 이 폴더를 꼭 함께 올립니다.
   `data/posts.json`을 고쳤다면 `node supabase/make-seed.mjs`로 `seed.sql`을 다시 만든 뒤 실행합니다.
4. **관리자 계정 만들기**: 대시보드 **Authentication → Users → Add user → Create new user**.
   관리자 이메일과 비밀번호를 넣고 **Auto Confirm User**에 체크한 뒤 만듭니다. 만들어진 사용자의 **User UID**를 복사합니다.
5. **관리자로 등록하기**: SQL Editor에서 (UID 자리에 복사한 값을 넣어) 실행합니다.
   ```sql
   insert into public.admins (user_id) values ('여기에-User-UID');
   ```
   관리자를 그만두게 할 때는 `delete from public.admins where user_id = '…';`
6. **아무나 가입하지 못하게 막기(권장)**: **Authentication → Sign In / Providers**(또는 Settings)에서 **Allow new users to sign up**을 끕니다.
   (꺼 두지 않아도 `admins` 표에 없는 사람은 글을 쓸 수 없지만, 필요 없는 계정이 생기지 않게 막아 둡니다.)
7. **홈페이지에 주소와 공개 키 넣기**: 대시보드 **Project Settings → API**(또는 API Keys)에서
   - Project URL (예: `https://abcd1234.supabase.co`)
   - 공개 키: 예전 방식 **anon public** 키(`eyJ…`로 시작) 또는 새 방식 **publishable** 키(`sb_publishable_…`)

   를 `assets/js/config.js`에 넣고 다시 올립니다.
   ```js
   window.TK_CONFIG = {
     supabaseUrl: "https://abcd1234.supabase.co",
     supabaseAnonKey: "eyJ…(공개 키)"
   };
   ```
   **service_role 키나 secret 키는 절대 넣지 마세요.** 이 파일은 누구나 볼 수 있습니다. 공개 키는 보여도 괜찮고, 권한은 2번의 규칙이 지킵니다.
8. **확인**: 홈페이지 ‘뉴스·영상’에 글이 그대로 나오는지, `/admin/`에서 로그인되는지 확인합니다.

## 관리자가 글 쓰는 법

1. 홈페이지 맨 아래 작은 **관리자** 링크(또는 `주소/admin/`)를 엽니다. 이 화면은 검색 엔진에 나오지 않습니다.
2. 관리자 이메일과 비밀번호로 **로그인**합니다.
3. **글 목록**에서 글마다 분류, 날짜, 게시함/숨김, 처음 화면에 보이는지가 보입니다. ‘분류로 골라 보기’로 줄여 볼 수 있습니다.
4. **새 글 쓰기**를 누르고 칸을 채웁니다.
   - **분류**: 종합뉴스 · TK 뉴스 · 진실알리기 · 행사·세미나
   - **제목**, **올린 날짜와 시간**(처음에는 지금 시각, 한국 시간), **행사 날짜**(행사·세미나일 때만, 넣지 않아도 됨)
   - **본문**: 문단 사이에 한 줄을 비웁니다. 인터넷 주소는 저절로 링크가 됩니다.
   - **유튜브 주소**: 유튜브 ‘공유’ 단추로 나온 주소를 그대로 붙여 넣습니다(`youtu.be/…`, `youtube.com/watch?v=…`, `shorts/…`, `live/…` 모두 됨). 알아보면 ‘영상을 알아보았습니다’라고 나옵니다.
   - **사진 고르기**: 여러 장을 한 번에 고를 수 있습니다. 올리기 전에 긴 쪽 1600픽셀로 저절로 줄어들고(사진 속 위치 정보도 지워짐), ‘앞으로/뒤로’로 순서를 바꿀 수 있습니다. 사진마다 **사진 설명**(화면 읽기용)을 써 주세요. **사진 아래에 보일 글**은 넣고 싶을 때만 씁니다.
     사진을 준비하는 동안에는 ‘저장하기’와 ‘미리 보기’ 단추가 ‘사진 준비 중…’으로 바뀌어 눌리지 않습니다. 새로 넣은 사진은 본문 아래에 놓입니다.
   - **보이는 곳**: 게시함/숨김, 처음 화면 ‘최근 소식’에 보이기
5. **미리 보기**로 홈페이지에서 어떻게 보일지 확인한 뒤 **저장하기**를 누릅니다. ‘저장했습니다’가 나오면 홈페이지에 바로 보입니다.
6. 고칠 때는 목록에서 **고치기**, 지울 때는 **지우기**(한 번 더 묻습니다. 지운 글과 그 글의 사진은 되살릴 수 없습니다).
   잠시 내리고 싶을 때는 지우지 말고 ‘숨김’으로 저장하세요.
   - 고칠 때 ‘올린 날짜와 시간’ 칸을 건드리지 않으면 올린 시각은 그대로(초 단위까지) 남습니다.
   - 옛 글의 사진·영상 자리와 숨은 링크(위 `after`, `video_after`, `links`)는 이 화면에서 바꾸지 않고 그대로 둡니다. 본문의 문단 수를 바꾸면 사진 자리가 한두 문단 어긋날 수 있습니다.
7. 관리자인지 확인하는 중에 인터넷·서버 문제가 생기면 ‘관리자인지 확인하지 못했습니다’와 **다시 시도** 단추가 나옵니다.
8. 사진을 올린 뒤 저장이 실패해서 ‘목록으로 (저장 안 함)’을 누르면, 올렸던 사진 파일도 저장소에서 지웁니다.
   다만 저장 도중에 창을 닫으면 어느 글에도 쓰이지 않는 사진 파일이 남을 수 있습니다. 가끔 SQL Editor에서 아래로 찾아 Storage 화면에서 지우면 됩니다.
   ```sql
   select o.name from storage.objects o
   where o.bucket_id = 'post-images'
     and not exists (select 1 from public.posts p, jsonb_array_elements(p.images) im
                     where im->>'src' like '%/post-images/' || o.name);
   ```

## 배포하기 (인터넷에 올리기)

정적 사이트라서 HTML 파일을 올려 주는 곳이면 어디든 됩니다(Cloudflare Pages, Netlify, GitHub Pages, 일반 웹 호스팅 등). 서버 프로그램은 필요 없습니다.

1. 저장소 파일을 **폴더 구조 그대로** 호스팅의 맨 위 폴더에 올립니다. `.git`, `README.md`, `CONTENT-TODO.md`, `supabase/`는 올리지 않아도 됩니다(올려도 해는 없음).
2. 기본 문서는 `index.html`, 없는 주소 쪽은 `404.html`로 정합니다(위의 정적 호스팅들은 저절로 그렇게 합니다).
3. **404.html은 주소가 `/`로 시작합니다.** 사이트를 도메인 맨 위(`https://국민주권운동.com/`)에 올린다는 전제입니다. 옛 주소(`/bbs/…`)처럼 하위 폴더 주소에서도 스타일과 메뉴가 깨지지 않게 하려는 것입니다.
   하위 폴더(예: `https://example.github.io/truthkorea/`)에 올릴 때는 404.html의 `href="/`, `src="/`를 그 폴더(`/truthkorea/`)로 바꾸고, `assets/js/legacy-redirect.js`의 `BASE`도 같은 값으로 바꿉니다.
4. 호스팅이 준 임시 주소로 먼저 열어 모든 쪽과 휴대전화 화면을 확인합니다.
5. **도메인 연결(DNS)**: 도메인 등록 업체의 DNS 관리 화면에서 호스팅이 알려 준 값으로 바꿉니다.
   - 한글 도메인 `국민주권운동.com`은 관리 화면에 따라 영문 변환 이름 **`xn--3e0b9b67w9mjb2nckd.com`**으로 넣어야 할 수 있습니다.
   - 맨 앞이 없는 주소(`@`)는 A 기록(또는 ALIAS/ANAME), `www`는 CNAME 기록으로 연결하는 것이 일반적입니다.
   - 바뀐 기록이 퍼지는 데 몇 분에서 하루 이상 걸릴 수 있습니다.
6. **보안 연결(HTTPS)**: 호스팅의 자동 인증서 발급을 켭니다.
   **지금 옛 사이트의 https 인증서는 2026년 8월 29일에 만료되어**, `https://국민주권운동.com`으로 들어오면 브라우저가 경고를 띄웁니다. DNS를 새 호스팅으로 옮기고 새 인증서가 발급되면 해결됩니다. 발급 뒤 `http://` 주소가 `https://`로 넘어가는지 확인합니다.
7. **카카오톡 미리보기**: 모든 쪽에 `og:title`(트루스코리아), `og:description`(자유대한민국 5,000만 국민주권운동!), `og:image`가 들어 있습니다.
   `og:image`와 `og:url`은 카카오톡이 절대 주소만 읽기 때문에 `https://xn--3e0b9b67w9mjb2nckd.com/…`로 적혀 있습니다. 도메인이 바뀌면 HTML 파일들에서 이 주소를 모두 바꿉니다.
   `og:url`은 주소가 늘 같은 쪽(처음, 단체 소개, 행사·세미나, 후원하기, 연락처)에만 있습니다. `post.html?id=…`, `news.html?cat=…`, 404 쪽에는 일부러 넣지 않았습니다.
   그래야 미리보기 프로그램이 실제로 보낸 주소(글 번호 포함)를 그대로 쓰고, 서로 다른 글이 한 주소로 합쳐지지 않습니다.
   미리보기 그림을 바꾸면 8개 HTML 파일의 `og:image:width`·`og:image:height`(지금 499×254)도 새 크기로 고칩니다.
   카카오톡은 미리보기를 한동안 저장해 두므로, 바꾼 뒤에는 카카오 개발자 사이트의 **공유 디버거**에서 주소의 캐시를 지웁니다.
   `post.html?id=…`(글 하나) 주소를 보내도 미리보기는 사이트 공통 제목·그림으로 나옵니다(글 제목은 화면을 열어야 보임).

## 고칠 때 알아 둘 것

- 모든 쪽의 머리글·메뉴·바닥글·아래 막대는 같은 모양이어야 합니다. 메뉴를 바꿀 때는 **모든 HTML 파일**(`index`, `about`, `news`, `events`, `post`, `support`, `contact`, `404`)의 `.gnb__list`, `.footer-menu__list`, `.quickbar`를 함께 고칩니다.
- 연락처·계좌가 바뀌면 모든 HTML 파일에서 `010-2705-5000`, `01027055000`, `suntrees@naver.com`, `212-910016-02504`, `21291001602504`를 찾아 바꿉니다.
- 아직 정해지지 않은 내용이 생기면 `<span class="ph" data-ph="KEY">[입력 필요: …]</span>`로 표시합니다(노란 바탕으로 보임). 지금은 화면에 이런 칸이 없습니다.
- 메뉴 칸은 휴대전화·태블릿 3칸(아주 좁은 화면이나 큰 글자에서는 2칸), 넓은 화면 6칸으로 저절로 놓입니다. 글자가 커지면 ‘·’ 뒤에서만 줄을 바꿉니다.
- 휴대전화에서는 ‘처음으로 › 쪽 이름’ 한 단계짜리 현재 위치 줄과 목록 쪽의 ‘전체 글’ 같은 목록 제목을 화면에서 숨깁니다(바로 위 메뉴·분류 단추의 진한 칸과 같은 내용). 목록 제목은 화면 읽기 프로그램에는 그대로 읽힙니다.
- 글 제목은 ‘·’ 바로 뒤에서 줄을 바꿀 수 있게 화면에 그릴 때 `<wbr>`을 넣습니다(글자는 그대로).

- 옛 원본 쪽과 비교: 20개 글의 본문+사진 설명이 옛 글과 낱말 단위로 똑같음. 사진 17장은 모두 원본과 바이트까지 같음. `assets/uploads/legacy/`에는 이 20개 글이 쓰는 파일(31개)만 있음.
- Supabase 경로(요청 주소·머리글·필터), 글 속 HTML·자바스크립트 주소가 글자로만 보이거나 버려지는지(XSS), 빈 목록·오류·다시 불러오기(초점 이동 포함)를 가짜 Supabase로 확인.
- 관리자 화면: 로그인, 관리자 확인 실패 시 ‘다시 시도’, 글 쓰기·사진 올리기·고치기·지우기, 사진 준비 중 저장 막기, 저장 실패 후 올린 사진 지우기, 날짜를 안 고치면 올린 시각 유지, 분류를 빨리 바꿔도 목록이 섞이지 않음, 재생목록 주소 거절을 가짜 Supabase로 확인.
- 인쇄(A4): 긴 글도 첫 쪽부터 나오고, ‘사진 크게 보기’·영상 안내·복사 단추 안내는 인쇄되지 않음.
- 옛 주소 옮겨 주기(`/bbs/board.php?…`, `&amp;wr_id=` 꼴 포함) 128가지: 옮긴 글 20개의 옛 주소는 그 글(숨긴 같은 글은 보이는 쪽)로, 옮기지 않은 옛 글 84개의 옛 주소는 모두 그 분류의 목록으로, 공지사항 등 다른 게시판은 처음 화면으로 가고, 없는 글 화면으로 가는 주소는 하나도 없음.
- 자바스크립트 끈 화면, 글자 크기 저장 실패, 고대비 모드도 확인.
- `0001_init.sql`과 `seed.sql`을 실제 PostgreSQL(PGlite)에서 실행해 글 20개(두 번 실행해도 20개), 권한 규칙(방문자 19개·일반 로그인 19개·관리자 20개), 정책 이름이 잘리지 않는지 확인.
- 저장소 전체(글자 파일)에서 쓰지 말라고 한 다른 계좌번호와 지운 자료실 쪽의 주소가 한 번도 나오지 않음을 검사 프로그램으로 확인.
